# نظام التقييم التربوي (ويب + تطبيق قابل للتثبيت على Android)

نظام تقييم تربوي عربي (RTL) مبني بـ **Next.js + PostgreSQL (Drizzle)**: خادم REST واحد، قاعدة بيانات واحدة، ومنطق تقييم واحد يشترك فيه الحاسوب والهاتف.

## ما الذي أُنجز فعليًا (ومُختبر)

| الوحدة | الحالة |
|---|---|
| تسجيل الدخول، أدوار (مدير/معلم)، جلسات آمنة، سجل العمليات | ✅ |

| استيراد جماعي: Excel (xlsx/xls) / CSV / JSON / لصق من Excel / قائمة أسماء | ✅ معاينة + أخطاء + تصحيح + معالجة التكرار (تجاهل / تحديث / إضافة بعد تأكيد) |
| استيراد الرقمنة: ربط الأعمدة (Nom، Date de naissance، Matricule…) وحفظ الربط | ✅ |

## التشغيل

```bash
# متطلبات: Node 20+، PostgreSQL
echo 'DATABASE_URL=postgresql://user:pass@127.0.0.1:5432/app_db' > .env
npm install
npx drizzle-kit push        # إنشاء الجداول
npm run build && npm start  # http://localhost:3000
```
أول زيارة تعرض شاشة الإعداد الأول (المؤسسة + حساب المدير + القسم الأول).

## الاختبارات
```bash
npx vitest run
```
تغطي: PDF لكل تلميذ، PDF القسم، أسماء عربية طويلة، أوضاع الطباعة، خيارات المحتوى، ZIP/PDF موحد/Excel/CSV/JSON لأقسام من **30 و50 و100** تلميذ (عدم فقدان بيانات، عدم تكرار، عدم وجود ملفات فارغة، فتح الملفات الناتجة)، وكذلك الاستيراد وكشف التكرار وتحليل الملفات القديمة.

## Android
لم يتم بناء APK أصلي في هذه البيئة (لا يوجد Android SDK/Flutter)، ولا أدّعي غير ذلك. المتاح والعامل:
* **تطبيق ويب قابل للتثبيت (PWA)** على Android: افتح الموقع في Chrome ← «إضافة إلى الشاشة الرئيسية». الواجهة متجاوبة للهاتف، والتصدير يعمل بالتنزيل والمشاركة عبر قائمة المشاركة في النظام والطباعة.
* للحصول على **APK** من نفس النسخة: انشر الخادم على HTTPS ثم استعمل Bubblewrap (Trusted Web Activity):
  ```bash
  npm i -g @bubblewrap/cli
  bubblewrap init --manifest https://YOUR-DOMAIN/manifest.webmanifest
  bubblewrap build   # ينتج app-release-signed.apk
  ```
  (أو PWABuilder.com). بهذا يبقى الهاتف والحاسوب على نفس قاعدة البيانات ونفس المنطق.
* تطبيق Flutter أصلي: يستهلك نفس واجهات `/api/*` دون تغيير في الخادم؛ لم يُنفَّذ هنا.

## الذكاء الاصطناعي
اضبط متغيرات الخادم فقط (لا مفاتيح في الواجهة):
```
AI_API_KEY=...
AI_BASE_URL=https://api.openai.com/v1   # أي مزوّد متوافق مع OpenAI
AI_MODEL=gpt-4o-mini
```
تُرسَل رموز مجهولة (S1, S2…) ونتائج المهارات فقط — لا أسماء ولا تواريخ ميلاد ولا ملاحظات نصية. دون مفتاح يعمل تحليل آلي بقواعد محلية، ويُوسَم صراحةً بأنه كذلك. جميع المخرجات «اقتراحات» تميَّز عن البيانات المسجلة.

## بنية المشروع
* `src/db/schema.ts` — الجداول (مؤسسات، مستخدمون، أقسام، تلاميذ، مواد، مهارات، فترات، تقييمات، تحليلات، استيراد، تصدير، سجل عمليات).
* `src/lib/pdf/` — محرك PDF عربي (تشكيل الحروف، bidi، خطوط Cairo المضمّنة في `assets/fonts`).
* `src/lib/export/files.ts` — Excel/CSV/JSON/ZIP.
* `src/lib/import.ts`، `src/lib/legacy.ts` — الاستيراد والترحيل.
* `src/server/` — المصادقة، تجميع بيانات التقارير، الذكاء الاصطناعي.
* `src/app/api/*` — واجهات REST. `src/app/(app)/*` — الشاشات.

## حدود معروفة (بصراحة)
* **ملفات المشروع الأصلي (`app.py`، `students_data.json`…) لم تكن متاحة في بيئة العمل**، لذلك لم أحلّل منطقها الفعلي. محوّل الترحيل يتعامل مع بنى JSON الشائعة (قائمة أو قاموس تلاميذ، تقييمات متداخلة، سجل بالتواريخ) ويحفظ ما لا يتعرف عليه في حقل `extra.legacy` دون فقدان. شغّله أولًا بوضع «تحليل فقط» على ملفك الحقيقي؛ وإن اختلفت البنية فسيُعدَّل المحوّل بسهولة (`src/lib/legacy.ts`). كذلك فإن قائمة المواد والمهارات الافتراضية قالب عام قابل للتعديل من الإعدادات وليس مأخوذًا من المشروع الأصلي.
* الخادم مبني بـ Next.js (TypeScript) بدل FastAPI، وPostgreSQL فقط (بدون SQLite محلي)، والواجهة PWA بدل Flutter؛ لأنها بيئة المنصة المتاحة، وتحقق شرط «قاعدة بيانات ومنطق واحد» للهاتف والحاسوب.
* لم يُختبر على أجهزة Android/طابعات حقيقية؛ اختُبرت ملفات PDF برمجيًا وبصريًا (تحويل إلى صور) في بيئة الخادم.
* صيغة XLS القديمة مدعومة عبر مكتبة SheetJS على أساس «أفضل جهد».
